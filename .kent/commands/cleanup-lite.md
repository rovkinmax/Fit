# Agent-owned Lite cleanup

Only the new Engineering Lite Workflow selects this procedure. FIT-1 and other
compatibility Workflows do not inherit it. Load the installed skill's worktree
contract through its canonical source binding.

Recover the incoming disposition, original authority and exact native
Task/project/source workspace/managed root/branch/PR/base/head identities.
Delivery requires observed authorized merge; non-delivery requires original
human authority for that disposition. Neither implies worktree/branch deletion
permission: verify the applicable original resource-deletion authority, or ask
for it while preserving resources.

Before effects, preserve the immutable plan/review references, verification
and candidate review, PR/CI and disposition evidence, native identity,
authority, original root/branch and before-state outside the retiring root.
Use an ordinary R2 document in the same genuine Task binding and CAS revisions;
read back exact bytes/digest before leaving. Do not invoke Agent `accept-plan`,
legacy caches, final ledger append/seal or Script Janitor. Verify R2 from the
actual current Session and Task; never fabricate a binding.
Retain and read back this proof while the original native Task worktree binding
is still usable. No post-delete R2 write or new Task-comment protocol is
required; final observed effects travel through the declared native
`cleanup_result`, not a storage-admission bypass.

Identify only proven task-owned sessions/shells/children. Release them through
their own supported handles, obtain fresh request-bound evidence, independently
check runtime inventory and recoverable Git state. Foreign/unknown owners or
unavailable exclusion block deletion, never authorize kill/force/sweeping.
When addressing another Session, use the explicit supported session selector.
Inventory all ignored/runtime materials, including caches, generated files and
hidden artifacts; Git-clean alone is insufficient. Record a disposition for
every material class before leave. Dispose only of explicitly authorized
reproducible caches; preserve meaningful artifacts outside the root with exact
digests and complete readback. Unknown materials, incomplete inventory or
unapproved disposal block deletion. Revalidate the full inventory, including
ignored files, immediately at the destructive boundary.

Use supported `kent worktree` leave/delete operations in the order required by
the actual installed CLI. Inspect CLI help and effective targeting before any
effect. Leave into the existing primary project workspace only through a
supported operation and verify actual native workspace identity. If this
cannot preserve genuine current Cleanup execution, block; do not invent a
replacement task/session, rebind a foreign owner or use manual Git removal.
After the owning Agent's supported leave, perform a separate subsequent Agent
step without `cd` or a `workdir` override: inspect `pwd -P` and
`kent worktree status --json`. Require actual primary cwd,
`target.worktree=null` and `problems=[]`. Scheduled leave is not release proof;
never delete the current execution root.

Record and inspect actual operation receipts. `scheduled` and successful
request submission are pending, not absence. Re-observe original path,
Git worktree registration and native inventory from outside that root.
Advance only after proven path/Git-registration absence, reported exact native
registration state and an explicit authorized local-branch disposition.
Never remove remote branches without separate permission.

On interruption, unknown outcome or retained target disappearance, settle
effects read-only first. Preserve the outside-root record. Do not retry
deletion, recreate a root, resume blindly, manually move the Task or infer
success from a queued resume. Missing supported recovery blocks only cleanup.
Carry final path/Git/native-registration and branch observations in the
existing native `cleanup_result` before normal completion.
