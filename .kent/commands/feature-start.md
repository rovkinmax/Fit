# Plan a Fit Change

Inspect the affected site behavior and existing verification. Resolve original
requirements and the actual native R2 installation/binding through the
qualified installed `kent-project-memory workflow` interface. An unregistered
profile, missing installation records or legacy response blocks; do not use
`.todo`, import old documents, fabricate native identity or initialize a store
from a feature Task.

At genuine first native ingress use `initialize-task` with the actual execution
root and current native Task/Session binding; a Script cannot invent that
first Agent ingress. An existing matching Task resolves normally; conflicting
identity blocks. Publish one authoritative working plan under the admitted
Task's R2 document key through `publish`, using the actual expected revision
for compare-and-swap and the adapter's declared request schema. Preserve retry
identity; settle stale/conflicting publication instead of overwriting it.
Read back the immutable revision and digest, and pass that exact external plan
locator through the native graph.

The plan names scope, acceptance checks, effects, constraints and original
decision references. Reproduce a defect before proposing its fix.

Name verification, PR/CI and terminal cleanup obligations with their owners.
Independent Plan Review precedes deterministic Plan Contract acceptance.
Material scope changes repeat that path; progress bookkeeping does not.
Do not treat a pending question, summary or accepted cache as human approval.
Only the actual configured acceptance Script may publish accepted state.
Do not manually write accepted heads, revision files or a local cache.
